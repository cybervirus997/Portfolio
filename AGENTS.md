# Working on this portfolio

Read `docs/JOURNEY_CONTEXT.md` before scanning the repository. It is the compact
architecture/content map. Read the relevant entries in `docs/IMPLEMENTATION_LOG.md`
for prior decisions and verification limits; then open only task-relevant files.

Preserve personal content in `src/data/` unless the user requests content changes.
Use npm + package-lock.json. Keep changes on the requested feature branch.
Respect reduced-motion, keyboard access, and touch layouts for animation changes.
After a meaningful change, update the log with decisions, replacements/removals,
checks actually performed, and remaining limitations. Refresh the short context map
when architecture changes. Never report browser/performance testing that did not run.
